00 / DESIGN LOGIC

RESEARCH TO DECISION

WHY THIS TOOL

사용성 연구를
실제 설계 판단에 연결하다.

연구에서 도출한 요인과 예측 모델을 디자이너가 해석하기 쉬운 화면으로 구성했습니다. 목표는 단일 점수를 보여주는 것이 아니라, 무엇을 확인하고, 어떤 요소를 먼저 조정하며, 변화는 어떻게 비교할지의 작업 순서를 명확히 하는 것입니다.

RESEARCH요인 도출TV 시퀀스·화면 요소
MODEL사용성 예측요인과 결과의 관계
TOOL화면 입력·분석요인값과 영향도 확인
DECISION대안 비교우선 변경할 요소 선택

프로토타입 조작. 시작 화면에서 실제 API 키를 입력하지 않고 ‘연결하고 시작하기’를 누르면 데모를 확인할 수 있습니다. 실제 개인·기업 API 키를 입력하지 마세요.

검증 범위. 이 페이지는 실제 제작된 화면과 인터랙션 구조를 설명합니다. 연결된 HTML 프로토타입은 데모 데이터로 작동하며, 화면에 표시된 53점·61점·63점 등은 사용성 향상을 실증한 별도 결과가 아닙니다. 이 프로토타입에서 외부 AI API 호출이나 예측 모델의 실시간 계산은 확인되지 않습니다.

STEP 01 — SCREEN INPUT

화면을 등록하고,
평가할 요소를 확인하다.

화면 이미지 업로드 후 탐색형 이동·설정/조작의 평가 유형을 확인하고, UI 요소의 수치 입력값을 조정하는 출발점입니다.

  1. 01TV 화면 원본평가할 UI를 입력값과 함께 확인
  2. 02요인별 수치 조정글꼴·이미지·항목 수를 명시
  3. 03분석으로 진행입력 완료 후 다음 단계로 이동
INTERFACE DECISION ↗

원본 화면과 수치 입력을 한 시야에.

화면을 보면서 항목별 값을 조정할 수 있도록 이미지 영역과 요인 입력 영역을 분리했습니다. 수치 조정 버튼과 도움말은 사용자가 추상적인 모델 변수를 실제 UI 속성과 연결하도록 돕습니다.

01 — CONTEXT

평가 유형 선택으로 시퀀스 맥락을 먼저 명시

02 — CONTROL

카테고리·썸네일·텍스트 항목 등 조정 가능한 요인 표시

02 / ANALYSIS

READ THE EVIDENCE

STEP 02 — USABILITY ANALYSIS

점수보다 먼저,
문제의 원인을 읽다.

요약 점수와 등급을 제시하되, 어떤 요인이 점수에 부정적으로 기여했는지 차트·설명·표를 통해 단계적으로 확인하는 화면입니다.

  1. 01요약 점수분석 결과의 빠른 개요 · 데모값
  2. 02영향도 그래프개선 우선순위를 요인별로 구분
  3. 03상세 근거 표요인·현재값·개선 방향을 연결
INTERFACE DECISION ↗

요약 → 영향도 → 근거 순서의 정보 계층.

상단에서는 분석 결과를 빠르게 이해하고, 중간 영향도 차트에서 우선 개선할 요인을 발견하며, 하단 상세 정보에서 관련 UI 특성을 확인합니다. 점수만으로 개선안을 결정하지 않도록 설명을 함께 배치했습니다.

01 — HIERARCHY

점수·등급으로 결과를 요약하고 영향도 차트로 원인을 제시

02 — TRACEABILITY

요인별 권장/적합 상태와 수치를 함께 표시

03 / RECOMMENDATION

FROM ISSUE TO OPTION

STEP 03 — ALTERNATIVE GENERATION

개선안은 제안하되,
선택권은 남기다.

분석에서 도출된 개선 대상 요인을 와이어프레임과 권장안으로 보여주고, 사용자가 변경 수준을 선택해 대안을 생성하도록 구성했습니다.

  1. 01화면 구조도수정할 요소를 화면 영역과 연결해 위치를 확인
  2. 02AI 권장 요인분석에서 취약했던 요인을 조정 대상으로 제시
  3. 03변경 수준 선택썸네일 2개·1개 증가 중 선택 후 대안 생성
INTERFACE DECISION ↗

원인과 조정 가능한 UI 항목을 연결.

영향도 분석의 결과를 바로 설계 변수로 연결해 피드백이 추상적인 문장에 머물지 않도록 했습니다. 와이어프레임은 수정 대상 영역을, 우측 패널은 변경 가능한 수량과 다음 행동을 보여줍니다.

01 — VISUAL TARGET

요인별 색과 영역 표시로 수정 위치 파악

02 — CHOICE

썸네일 수 증가 등 사용자가 조정안을 선택

STEP 04 — BEFORE / AFTER

변경된 화면과
예상 점수를 함께 보다.

원본 화면과 개선안을 나란히 배치해 시각적 변화, 조정된 요인값, 예시 점수 차이를 함께 검토하는 비교 화면입니다.

  1. 01기존 TV UI실제 캡처를 기준 화면으로 고정
  2. 02개선 구조안변경된 썸네일 배치를 같은 시야에서 비교
  3. 03점수 비교 · 데모값53 → 61은 시연용 예시이며 실증 개선 수치가 아님
INTERFACE DECISION ↗

평가 결과를 ‘수정할지 말지’의 판단으로 연결.

두 화면을 같은 시야에서 비교해 숫자 변화만이 아니라 구조가 어떻게 달라지는지도 볼 수 있도록 했습니다. 실제 결과 검증과 혼동되지 않도록 이 화면의 점수는 데모 예시값으로 해석해야 합니다.

01 — SIDE BY SIDE

02 — DECISION SUPPORT
