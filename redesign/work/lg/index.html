THE CONTEXT

멀리서 조작하는 화면.
더 명확한 판단 기준이 필요했습니다.

콘텐츠와 기능이 한 화면에 쌓이는 TV. 화면에서 떨어진 사용자는 리모컨으로 항목을 탐색하고, 원하는 기능을 선택해야 합니다.

이 프로젝트는 TV UI 요소가 사용성에 미치는 영향을 실험으로 살피고, 그 결과를 디자인 의사결정에 활용하는 도구의 UI로 구체화했습니다.

MY CONTRIBUTION

대표 시퀀스 선정, 실험과 예측 모델 개발은 연구팀의 공동 작업입니다. 저는 요구사항에 맞춘 AI Design Tool UI 프로토타입 제작·수정, 보고와 검토를 위한 자료·이미지 조사 및 시각 자료 구성에 참여했습니다.

01 / RESEARCH FRAME

화면을 보기 전에,
사용자의 목적부터 좁혔습니다.

검색·시청·제어의 목적에서 대표 시퀀스를 정리하고, 비교할 수 있는 화면과 사용성 요인을 정의했습니다.

  1. 01

    목적과 시퀀스 정의

    webOS 기능과 이용 목적을 기준으로 평가할 작업을 선정

  2. 02

    사용성 요인 선별

    문헌·가이드라인과 실제 UI에서 측정할 변수를 정리

  3. 03

    실험과 모델 개발

    주요 요인의 영향과 사용성 예측 모델을 연구팀이 분석

  4. 04

    도구 UI로 연결

    입력·분석·대안·비교의 흐름을 프로토타입으로 구체화

THE DESIGN CONNECTION

모델의 숫자를 사용자가
다룰 수 있는 입력과 판단으로.

탐색형의 썸네일 항목 수, 설정·조작형의 텍스트·아이콘 크기처럼 주요 요인을 화면에서 확인하고 조정하도록 연결했습니다. 점수를 제시하는 것에 더해, 무엇을 검토하고 바꿀 수 있는지 보이게 하는 데 초점을 두었습니다.

04 / AI DESIGN TOOL

하나의 작업이,
다음 판단으로 이어지도록.

입력 → 분석 → 대안 → 비교. 연구의 설명을 실제 UI 작업 흐름으로 옮겼습니다.

  1. INPUT
  2. ANALYZE
  3. RECOMMEND
  4. COMPARE
01 / INPUT

평가할 화면과
요인값을 먼저 확인합니다.

TV UI를 입력한 뒤 평가 유형을 선택하고 화면 요소의 값을 검토·조정합니다.

02 / ANALYZE

점수 뒤의
영향 요인을 읽습니다.

점수·등급과 함께 요인별 영향을 보여주어, 무엇부터 검토할지 판단하도록 구성했습니다.

03 / RECOMMEND

바꿀 요인을 선택하고,
권장안을 검토합니다.

사용자가 조정하는 영역과 AI 권장 패널을 구분해, 대안 생성의 입력과 제안을 함께 확인하게 했습니다.

04 / COMPARE

기존 화면과 대안을,
같은 기준으로 비교합니다.

As-Is / To-Be UI와 요인값·예측 점수의 차이를 나란히 읽도록 구성했습니다.

BEYOND THE MAIN FLOW

작업을 이어가는 환경도
한곳에서 확인하도록.

작업 이력과 API 연결, 모델·평가 기준, 저장·보안 옵션을 별도의 설정 구조로 정리했습니다.

05 / REFLECTION

화면의 이유를,
설명할 수 있는 디자이너로.

연구의 결과를 이해하는 일과,
사용자가 다룰 수 있는 화면으로
구체화하는 일은 연결되어 있었습니다.

학부연구생으로서 연구진의 요구를 프로토타입으로 옮기고, 중간 검토와 피드백을 반영했습니다. 이 과정에서 결과물의 시각적 완성도만큼 판단 근거를 짧고 명확하게 공유하는 일이 중요함을 배웠습니다.

다음에는 작업의 목적과 완료 기준을 더 일찍 구조화하고, 연구의 맥락을 스스로 설명하며 대안을 제안하는 역량을 넓혀가고자 합니다.
