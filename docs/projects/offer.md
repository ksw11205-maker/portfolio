# OFFER

공통 기준은 [DESIGN.md](../../DESIGN.md), 출처와 채택 범위는 [references.md](../design/references.md)를 따른다. 기존 `OFFER/offer/DESIGN.md`의 제품 전용 내용을 이 문서로 통합했다.

## 확인된 콘텐츠와 범위

- 목적: 브랜드별 프로모션의 기간·혜택·상태를 빠르게 비교한다. 서로 다른 브랜드 이미지에도 서비스 UI는 동일한 정보 구조를 제공한다.
- 제품 구현은 `OFFER/offer/`; 홈, 탐색, 브랜드 상세, OFFER 상세, 관심 브랜드, 저장한 OFFER의 여섯 화면이다.
- 메인의 요약은 “흩어진 브랜드 혜택을 한곳에서 빠르게 비교하는 경험.”이다. 2026-10-19부터 메인 썸네일과 VIEW CASE STUDY는 `/work/offer/case-study.html`로 연결한다. 표지의 View Site는 기존 제품 `/work/offer/index.html`을 새 탭에서 연다. 제품의 기존 경로·데이터·기능은 유지한다.
- 상세 원본은 `OFFER/case-study/`의 HTML·CSS·JS이며 `portfolio-shell/build.cjs`가 `/work/offer/`에 복사한다. 생성본은 직접 편집하지 않는다. 배경 → 방향·디자인 시스템 → 흐름 → 주요 UI → 반응형 → 브랜드 연결 → 마무리 순서이고 각 장에 독립 앵커를 부여했다.
- 상세에는 기존 제품 화면을 고정 기기 폭의 비상호작용 iframe으로 표시한다. 실제 사이트 동작 확인은 View Site로 이동한다. 가상 행사, 공식 홈페이지 연결, 미구현 실시간 연동을 명확히 구분한다.
- README의 데이터 설명: 12개 브랜드, 18개 가상 프로모션. 2026년 9월 샘플 날짜를 고정하며 실제 행사·성과로 제시하지 않는다.

## 상세페이지 벤토 그리드 — 2026-10-19

- 사용자 지정 방향: 크기가 다른 모듈이 맞물리는 벤토 그리드. 참고로 전달된 Notion URL은 본문 접근에 실패했으므로 해당 페이지를 관찰하거나 복제한 결과로 설명하지 않는다.
- 적용 범위는 `OFFER/case-study/case-study.css`와 빌드 출력이다. 제품 UI, 포트폴리오 쉘의 테마, 기존 목차·View Site 동선은 유지한다.
- 배경은 웜그레이 `#f1f1ed`, 패널은 화이트·차콜·뉴트럴, 간격은 16px(모바일 12px), 모서리는 24px(모바일 20px). 주황은 기존 색상 견본에 제한한다.
- 표지는 소개 블록과 세 기기 블록으로, 주요 화면은 8:4 비대칭으로 묶는다. 배경의 브랜드 묶음과 문제 정의, 세 설계 원칙, 디자인 시스템, 반응형 설명도 정보량에 따라 모듈화한다. 카드 높이는 내용에 따라 확장하며 텍스트를 고정 높이로 자르지 않는다.
- 태블릿에서 주요 UI는 6:6, 모바일은 문서 순서대로 1열 전환한다. 작은 화면에서 반응형 설명은 기기 도형과 설명을 가로로 묶어 읽는 크기를 유지한다.

## 콘텐츠 위계와 디자인 예외

1. 목록: 이미지 → 브랜드·행사명 → 최대 할인율 → 기간 또는 D-Day.
2. 상세: 할인율 → 기간 → 핵심 혜택 → 참여 브랜드 → 이용 조건 → 공식 페이지 CTA.
3. ‘최대’ 할인율·제외 조건·종료 여부를 숨기지 않는다. 가상 샘플의 링크가 브랜드 공식 홈으로 이동한다는 점을 표시한다.

- 사진과 브랜드 이미지를 크게 보여주되 카드 텍스트는 비교 정보에 집중한다.
- 일반 카드 표면에는 그림자·장식 그라데이션을 추가하지 않는다. 검색 진입을 드러내는 약한 그림자는 허용한다. 현재 저장 버튼·스크롤 헤더의 국소 그림자는 카드 전체 표면과 구분한다.
- 주황은 혜택·마감 상태에 제한하고 일반 버튼과 내비게이션은 중립색을 사용한다. 포트폴리오 메인의 블루를 제품 전체에 적용하지 않는다.
- 메인 임시 썸네일 배경 `#111e37`은 제품 팔레트가 아니다.

## 제품 전용 토큰과 구현 상태

아래는 기존 코드에서 확인한 값이다. 공통 토큰의 예외로 이 제품 범위에만 유지하며 새 권장값을 추가하지 않는다.

| 역할 | 현재 값·위치 |

| 폰트 | 로컬 `Pretendard Variable`, `assets/fonts/PretendardVariable.woff2` |

| 폭·거터 | `--page-width:1440px`, 거터 `64/40/20px` |
| 간격 | 기본 8px 단계; 그리드 `24px`, 최종 모바일 `14px`; 섹션 기본 `104px`, 최종 모바일 `68px` |
| 라운드·선 | 카드 `16px`·모바일 `12px`, 컨트롤 `999px`, 선 `1px solid #e7e7e3` |

- 메인 상품 구성은 대표 1개와 보조 2개, 후속 컬렉션은 4열부터 축소된다. 모바일은 내용에 따라 1~2열로 바뀐다.
- 모바일 홈 순서는 Hero → Popular → Ending Soon → Categories → New → Followed Brands다. 세부 화면 구성은 구현 README를 확인한다.
- 저장·관심 선택은 `aria-pressed`, 일정은 예정·D-Day·종료 문구, 결과 없음은 복구 동선, 저장 실패는 안내를 제공한다.
- 기준 토큰은 `css/variables.css`, 공통·컴포넌트는 `css/common.css`·`css/components.css`, 반응형은 `css/responsive.css`에 있다. 마지막 로드되는 `css/design-refresh.css`의 재정의를 함께 확인한다.

## 화면별 기획과 제품 고도화 — 2026-10-26

- 사용자의 기존 결과물을 바탕으로 여섯 화면을 개선했다. 홈은 검색과 브랜드 발견, Explore는 검색·카테고리·브랜드·상태·정렬 조합, 상세는 최대 할인과 적용 조건, Saved는 개별 행사 재확인, Favorites는 브랜드 관리, 브랜드 상세는 상태별 혜택 모아보기를 담당한다.
- 가상 컬렉션의 기준일을 `2026-09-24`로 명시하고 모든 제품 화면 상단에 표시한다. `nike-members`, `muji-season`은 예정 상태를 보여주는 가상 일정이다. 실제 진행 중인 행사로 표현하지 않는다. JSON과 로컬 fallback snapshot은 동일하게 유지한다.
- 검색 조건은 URL에 남긴다. 결과 0건은 조건 초기화, 저장 상태별 0건은 전체 저장, 브랜드 상태별 0건은 해당 브랜드 전체 목록으로 돌아간다. 종료 항목을 저장 목록에서 자동 삭제하지 않는다.
- 상세페이지는 배경 → 방향 → 흐름 → 여섯 화면의 사용자 목적·기능·배치 이유·예외 상태 → 반응형 비교 → 공식 홈페이지 연결 → 다음 검증 과제로 이어진다. 사용자 테스트 성과나 실제 제휴를 가정하지 않는다.
- `OFFER/case-study/case-study-assets/`의 이미지는 실제 브라우저에서 캡처했다. Saved/Favorites는 UI에서 저장·팔로우한 샘플 상태다. 상세페이지의 이미지는 크기 속성으로 공간을 미리 확보하고 지연 로딩한다. `portfolio-shell/build.cjs`가 이미지까지 복사한다.
- 확인: JS 문법, 빌드, diff 공백 오류; 1440px 4열·834px 2열·390px 1열; 여섯 제품 화면과 상세페이지의 모바일 가로 넘침; 복합 필터와 0건 복귀; 저장 지속·상태 분류·해제 후 초점; 팔로우 반영; 브랜드 상태 전환; 모바일 메뉴 Escape; 상세 CTA 목적지와 새 탭 안내.
- Figma OFFER 페이지는 12장으로 구성했다. 캡처는 실제 화면의 벡터 변환 레이어이며 설명은 편집 가능한 텍스트다. LG 페이지는 수정하지 않았다.
