## 2. 서비스 정의 — 확정

CAFÉKOK은 개인의 카페 취향과 방문 목적을 결합해 카페 선택을 돕는 서비스다.

- 문제의식: “선택지는 많아졌지만, 고르는 기준은 더 복잡해졌다.”
- 핵심 가치: “내 취향과 오늘의 목적에 맞는 카페를 찾는다.”
- 취향 6축: 분위기 / 공간 / 좌석 / 메뉴 / 가격 / 이동반경.
- 방문 목적 예시: 공부 / 데이트 / 친구와 만남 / 드라이브.
- 핵심 흐름: 취향 입력 → 취향 프로필 확인 → 방문 목적 선택 → 추천 카페 비교 → 상세 정보 확인.

위 내용은 사용자가 확정한 서비스 방향이며, 사용자 조사로 입증된 결과를 뜻하지 않는다. 6축의 측정 방식, 점수, 추천 가중치는 미확정이다. 임의의 알고리즘이나 정밀한 추천 정확도를 만들어 설명하지 않는다.

## 4. 디자인 기준 — 확정

### 제작 대상과 콘셉트

제작 대상은 카페콕 서비스의 UX 설계 과정과 결과를 보여주는 **포트폴리오 상세 페이지**다. 확정 콘셉트는 **따뜻한 건축적 미니멀**이다.

> 밝은 벽처럼 여유로운 바탕, 창틀처럼 명확한 정보 구조, 나무와 조명처럼 절제된 온기.

사용자가 설명한 참고 사진은 아이보리 외벽, 직사각형 창, 우드 벤치, 갈색 실내, 작은 앰버 조명, 회색 석재, 사람들이 머무는 장면으로 이루어진 카페 외관이다. 해당 사진 파일은 저장소에서 확인되지 않아 **미첨부 레퍼런스**로 기록한다. 위 설명은 사용자 제공 정보이며 사진을 직접 확인한 관찰이 아니다.

참고할 요소는 색의 비중, 여백, 정돈된 구조와 생활감이다. 카페 외관이나 창문을 웹 UI에 그대로 재현하지 않는다.

### 포트폴리오 공통 스타일과의 경계

- 기존 상세 페이지의 내비게이션, 뒤로 가기, 프로젝트 이동 구조를 우선 활용한다. 현재 확인된 상세 구조는 공통 헤더·푸터와 `/#work`로 돌아가는 링크이며, 프로젝트 간 이전·다음 이동은 구현된 것으로 간주하지 않는다.
- 공통 콘텐츠 폭, 반응형 규칙, 접근성, 기본 인터랙션 원칙은 DESIGN.md를 따른다.
- 저장소에 이미 정의된 공통 구조를 우선 활용한다.
- 카페콕 케이스 스터디 본문에는 아래의 밝고 따뜻한 스타일을 적용한다. 제품 UI 목업 내부의 컴포넌트 규칙은 실제 제품 디자인을 따른다. 본문의 기준을 미확인 제품 디자인에 소급 적용하지 않는다.
- 메인 포트폴리오의 다크 배경, 대형 마퀴, 메탈 소재, 강한 주황색을 카페콕 본문에 자동 적용하지 않는다.
- 기존 공통 CSS를 덮어쓰지 않는다. 향후 구현 시 카페콕 범위 안에서 스타일을 관리하며 다른 프로젝트와 공통 스타일에 영향을 주지 않는다.

- 넉넉한 바깥 여백과 일관된 정렬선을 사용한다.
- 한 섹션에는 하나의 핵심 메시지를 둔다.
- 카드형 편집 구성을 사용하되 정보 중요도에 따라 카드 크기와 비율을 달리한다. 모든 내용을 동일 크기로 배치하거나 모든 섹션을 동일한 3열 카드로 반복하지 않는다.
- 카드는 벽에 정돈되어 배치된 패널처럼 담백하게 표현한다. 본문 정보 카드의 모서리는 8~12px 수준으로 절제하며, 그림자는 기본적으로 생략하고 배경색 차이와 얇은 선으로 구분한다.
- 위 카드 기준은 상세 본문용이다. 제품 UI 목업 내부의 컴포넌트 규칙은 실제 제품 디자인을 따른다.
- 데스크톱에서는 설명과 근거·화면을 나란히 배치하고, 모바일에서는 의미 있는 읽기 순서로 재배치한다.
- 16:9 구성은 개별 시각 자료에 활용할 수 있지만 웹 섹션 전체를 16:9나 고정 높이에 가두지 않는다.
- 본문·카드·버튼은 향후 HTML/CSS로 구현할 대상이다. 작은 글씨가 들어간 긴 이미지 한 장으로 상세 페이지 전체를 만들지 않는다.

### 타이포그래피

- 상세 페이지의 제목과 본문은 Pretendard를 기준으로 한다. 제목은 크기·굵기·여백으로 위계를 만든다.
- Cafe24 써라운드는 로고·브랜드명 등 제한된 강조 영역에만 사용한다. 긴 본문이나 모든 섹션 제목에 장식 서체를 반복하지 않는다.
- 큰 영문 장식보다 한국어 핵심 메시지의 전달력을 우선한다.
- 문단 폭과 행간을 충분히 확보하고, 여백 확보를 위해 글자를 지나치게 작게 만들지 않는다.
- 서체 사용 방향은 확정되었으나 파일 확보·로딩 검증은 별개다. 구현 단계에서 폰트 파일과 기존 로딩 상태를 확인하고 확보되지 않은 파일을 있다고 가정하지 않는다.

### 사진과 이미지

- 낮은 채도, 자연스러운 명암, 따뜻한 중성색을 기준으로 한다.
- 좌석 간격, 창가, 테이블, 대화하는 사람 등 ‘공간에 머무는 방식’이 보이는 사진을 우선한다. 커피잔 클로즈업만 반복하지 않는다.
- 사진은 분위기 조성과 서비스 맥락 전달에 사용하며 내용 없는 장식으로 남발하지 않는다.
- 필름 입자감은 사진 안에서만 살린다. 본문 배경에는 거친 종이·노이즈 텍스처를 넣지 않는다.
- 화면 전체를 누렇게 보정하거나 세피아 필터를 적용하지 않는다.
- 생성 이미지는 배경·일러스트 등에 사용할 수 있지만 실제 앱 화면·IA·리서치 결과를 대체하지 않는다.
- 미확보 이미지와 제품 화면은 필요한 에셋으로 기록한다. 이번 작업에서 임의의 최종 자료를 만들지 않는다.

### 금지사항

- 갈색으로 가득 찬 페이지.
- 과도하게 둥근 카드와 알약형 장식.
- 글래스모피즘, 강한 그라디언트, 두꺼운 그림자.
- 커피콩·머그 아이콘의 장식적 반복.
- 창문·벽돌·나무 질감을 직접 모방한 UI.
- 내용보다 분위기 사진이 지배하는 구성.
- 수행하지 않은 조사·검증 결과나 임의의 수치 생성.

## 5. 자료와 데이터 관리

원본 에셋 준비 위치는 `cafekok/assets/`이며 `brand/`, `screens/`, `research/`로 구분한다. 현재 세 폴더는 비어 있다. 기존 자산을 이동하거나 다른 프로젝트의 자료를 카페콕 자료로 전용하지 않는다.

- ‘확보됨’은 실제 파일 경로를 기록한다. 아래 저장소 경로는 `AI/` 기준이다.
- ‘필요함’은 사용할 섹션과 필요한 자료를 기록한다. 예정 폴더는 확보된 파일 경로가 아니다.
- ‘임시 자료’는 현재 위치와 교체 이유를 기록한다.
- 로고, 화면, 사진을 확보했다고 가정하지 않는다. 샘플 카페 정보는 실제 운영 정보와 구분한다.
- 참고 이미지나 임시 UI는 최종 디자인으로 취급하지 않는다. 외부 자료의 출처·라이선스를 보존한다.

## 6. 확인된 저장소 구조와 구현 준비

확인일: 2026-09-28. 아래는 저장소 파일을 확인한 사실이며 실행·화면 검수 결과를 의미하지 않는다.

- `portfolio-shell/dist/data.js`: 표시 제목 `CAFEKOK`, 분류 `Cafe Recommendation UX/UI`, 요약 “취향과 방문 목적을 연결해, 나에게 맞는 카페를 찾는 경험.”
- `/work/cafekok`는 제목과 준비 안내만 있는 상태다.
- 기존 앱은 `portfolio-shell/`의 HTML·CSS·JavaScript ES modules 구성이다. 별도 UI 프레임워크 없이 `dist/`에 소스와 배포 파일이 함께 있다.
- 저장소에서 `package.json`과 패키지 매니저 잠금 파일은 확인되지 않았다. 패키지 매니저나 설치 명령을 새로 가정하지 않는다.
- 라우팅은 `dist/app.js`가 `location.pathname`과 프로젝트 slug를 읽는 방식이다. `server.cjs`는 확장자 없는 요청에 공통 `dist/index.html`을 반환한다.
- 스타일은 `dist/styles.css`의 일반 CSS·커스텀 속성·미디어 쿼리로 관리하며 `dist/index.html`에서 로드한다. Pretendard Variable은 CDN으로 로드한다.
- CAFÉKOK은 독립 앱이 아니라 기존 포트폴리오 앱의 하위 상세 페이지로 준비한다. `cafekok/`은 문서와 원본 에셋 준비 공간이며 별도 앱·중복 의존성·AGENTS.md를 만들지 않는다.
- 기존 서버의 공개 루트는 `portfolio-shell/dist/`다. `cafekok/assets/`는 현재 직접 제공되지 않는다. 후속 구현 시 필요한 에셋의 배포 위치와 참조 방식을 기존 앱에 맞춰 정하며, 이번에는 복사·연결하지 않는다.
- 이번 변경은 카페콕 문서와 준비 공간에 한정한다. 공통 지침·메인 포트폴리오·다른 프로젝트 파일은 수정하지 않는다.

## 7. 미확정·후속 확인 항목

- 실제 화면·사진·연구 자료와 기간·역할·기여도·도구·성과.
- 6축의 측정 방식·점수·추천 가중치. 확정 자료가 없으면 구체적인 알고리즘 설명은 생략한다.
- 4절의 콘셉트·6색 팔레트·서체 사용 방향은 확정이다. 미첨부 레퍼런스 원본, 게재용 사진, 폰트 파일 확보·사용 조건·실제 로딩 상태는 후속 확인 대상이다.
- 텍스트 대비와 실제 콘텐츠에 따른 문단 폭·행간·반응형 배치 검증은 구현 단계에서 수행한다.
- 기존 IA의 예외 흐름 포함 여부와 보완 필요 항목.
- 실제 검증 수행 여부. 자료가 없으면 향후 검증 계획과 현재 한계를 명시한다.

## 8. 채택한 포트폴리오 전개 레퍼런스

2026-09-28 사용자 요청으로 문선의 포트폴리오, 유니클로 UI 리디자인, 이해민 포트폴리오 캡처를 확인했다. 출처·원본 캡처·관찰 내용·사용 조건은 [레퍼런스 목록](../design/references.md#참고-캡처)에서 관리한다.

- 문선의 포트폴리오: 배경과 조사에서 설계 방향을 도출하고, 기능별 화면을 사용자 이점 중심의 제목으로 설명하는 전개를 참고한다.
- 유니클로: 문제와 해결 방향의 대응, 조건·선택을 포함한 사용자 흐름, 큰 대표 화면과 세부 확대·짧은 주석의 연결, 검증·회고로 마무리하는 구성을 참고한다.
- 이해민의 디무브: 신규 서비스의 대상 사용자·상황 → 행동 → 제공 가치 → 기능을 연결하는 시나리오 설명을 참고한다. 카페콕은 공부·데이트 등 방문 목적별로 필요한 판단 정보가 어떻게 달라지는지 보여줄 수 있다. 이는 후속 설명 방향이며 실제 사용자 조사나 페르소나를 확보했다는 뜻은 아니다.
