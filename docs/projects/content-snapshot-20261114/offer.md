02 / PROBLEM HYPOTHESIS

### 혜택은 어디에나, 비교 기준은 제각각.

브랜드 공식 채널, SNS, 쇼핑 플랫폼에 흩어진 정보. 할인 조건과 진행 기간을 다시 해석해야 할 수 있다는 문제 가설에서 출발했습니다.

분산된 채널 → 서로 다른 표기 → 조건 재확인 → 비교 부담

03 / RESEARCH PLAN

### 답을 꾸미기 전에, 확인할 질문부터.

사용자 조사 결과가 아닌, 서비스의 문제 가설을 확인하기 위한 탐색적 조사 계획입니다.

RESEARCH PENDING · 목표 20–30명 · 응답 수집 전

#### 어디서 혜택을 발견하는가?

공식 홈페이지 · SNS · 쇼핑 플랫폼

#### 무엇을 먼저 확인하는가?

할인율 · 최종 가격 · 기간 · 조건

#### 어느 과정이 번거로운가?

정보 분산 · 표기 차이 · 만료 정보

06 / KEY UX / DISCOVER

### 좋아할 만한 혜택을 먼저 발견하도록.

검색할 대상이 정해진 사용자와 먼저 둘러보려는 사용자의 시작점을 함께 제공합니다.

검색으로 바로 진입

브랜드나 행사가 정해져 있다면 검색을 첫 행동으로 제공합니다.

브랜드 발견

검색어가 없어도 브랜드와 편집된 혜택을 탐색할 수 있습니다.

인기 혜택 편집

대표 행사를 먼저 보여주고 탐색의 단서를 제공합니다.

07 / KEY UX / COMPARE

### DIFFERENT BRANDS. ONE STANDARD.

검색·필터·정렬과 카드의 정보 위계를 하나의 탐색 경험으로 연결했습니다.

SEARCH

브랜드와 행사 이름으로 접근

FILTER

카테고리와 진행 상태로 후보 좁히기

SORT

조건과 별개로 비교 순서 선택

OFFER CARD

브랜드·혜택·기간을 같은 순서로 제시

실제 실행본의 전체 혜택 화면입니다. 위 버튼으로 조건을 적용한 캡처와 비교할 수 있습니다.

08 / KEY UX / DECIDE

### 할인을 확인했다면, 이제 이용 조건을.

어떤 행사인지, 언제까지 적용되는지, 이용하려면 어디로 이동해야 하는지를 구분합니다.

행사와 브랜드

누가 어떤 프로모션을 제공하는지 확인

기간과 참여 조건

할인율 다음에는 적용 범위와 기간 판단

저장과 이동

나중에 다시 볼 관심과 공식 사이트 이동을 구분

캡처의 프로모션은 데모용 가상 데이터입니다. 실제 행사·제휴·할인 보장이 아닙니다.

09 / SAVED & FAVORITES

### 관심이 남는 방식은 두 가지입니다.

개별 행사와 브랜드에 대한 관심을 같은 저장 행동으로 섞지 않았습니다.

SAVED / 행사 단위

#### 지금 결정하지 않아도, 다시 찾을 수 있도록.

저장한 혜택의 기간과 상태를 다시 확인합니다.

FAVORITES / 브랜드 단위

#### 좋아하는 브랜드의 다음 혜택으로.

관심 브랜드를 모아 해당 브랜드의 혜택을 다시 탐색합니다.

11 / RESPONSIVE WEB

### ONE EXPERIENCE. ADAPTIVE LAYOUTS.

카드의 읽는 순서는 유지하고, 화면 폭에 따라 콘텐츠 밀도와 탐색 요소의 배치를 조정했습니다.

CAPTION: 01 / DESKTOP 넓은 화면에서 비교 실제 1440px 캡처 · 4열 탐색

CAPTION: 02 / TABLET 카드 밀도 조정 실제 768px 캡처 · 2열 탐색

CAPTION: 03 / MOBILE 한 번에 한 카드씩 실제 390px 캡처 · 1열 탐색

13 / FINAL PROTOTYPE

### 디자인에서 끝내지 않고, 브라우저에서 동작하도록.

HTML · CSS · JavaScript로 구현한 반응형 데모입니다. 검색·조건 적용·저장·브랜드 팔로우를 실제 실행 사이트에서 확인할 수 있습니다.

이번 상세페이지의 캡처는 현재 저장된 실행본에서 새로 촬영했습니다. 가상 혜택과 브라우저에 저장한 샘플 상태를 사용했습니다.
