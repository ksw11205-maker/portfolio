## CAFÉKOK

Planning · UX/UI Design

TOOL

01 / OVERVIEW

### 오늘은 어떤 카페가 나와 잘 맞을까요?

평소 좋아하는 카페의 분위기는 같아도, 오늘 방문하는 목적은 달라집니다. 카페콕은 개인의 취향과 오늘의 방문 목적을 함께 고려해 카페를 찾고 비교하고 선택하도록 돕는 모바일 서비스입니다.

CAPTION: TASTE × TODAY’S PURPOSE

02 / BACKGROUND

### 많은 카페 중, 나에게 맞는 곳은?

카페는 많지만, 취향과 방문 목적에 맞는 곳을 고르는 과정에는 여러 번의 확인과 비교가 필요합니다.

#### 찾는 일에서, 고르는 일로.

카페의 수보다 중요한 것은 선택의 기준입니다. 정보 탐색의 부담을 줄일 수 있을까 하는 질문에서 시작했습니다.

- 검색

- 정보 확인

- 조건 비교

- 최종 선택

03 / SERVICE CONCEPT

### 카페 선택의 두 가지 기준, 취향과 목적

평소 선호하는 공간에 오늘 방문하는 이유를 더합니다. 복잡한 조건을 직접 조합하기보다, 선택의 기준을 먼저 정리하도록 구성했습니다.

CAPTION: CAFÉKOK

SIX TASTE DIMENSIONS

#### 취향은 여섯 가지 기준으로.

취향을 먼저 정리하고, 오늘의 방문 목적은 별도로 선택합니다. 두 입력을 하나의 추천 흐름으로 연결했습니다.

- 01 분위기 ATMOSPHERE

- 02 공간 SPACE

- 03 좌석 SEATING

- 04 메뉴 MENU

- 05 가격 PRICE

- 06 이동 반경 DISTANCE

실제 취향 점수나 사용자 조사 결과를 나타낸 그래프가 아닌, 프로토타입의 입력 항목을 정리한 정보 구조입니다.

### 취향 설정에서, 다음 방문까지.

개인의 취향을 설정하고, 오늘의 목적에 맞춰 후보를 살펴봅니다. 선택한 카페와 취향 정보를 다시 확인하는 흐름까지 연결했습니다.

06 / MAIN EXPERIENCE

### 취향이 선택으로 이어지는 화면

실제 프로토타입으로 주요 화면의 사용 흐름을 살펴봅니다. 각 화면의 역할과 사용자의 다음 행동을 함께 설명합니다.

01 / ONBOARDING

#### 첫 인상은 가볍게, 시작점은 분명하게.

서비스의 성격을 사진과 한 문장으로 전달하고 취향 질문으로 이어집니다.

CAPTION: ONBOARDING · 실제 프로토타입

CAPTION: QUIZ · 실제 프로토타입

단일 시작 행동

첫 화면의 버튼은 취향 설정이라는 다음 행동에 집중합니다.

여섯 가지 질문

분위기·공간·좌석·메뉴·가격·이동 반경을 나누어 입력합니다.

02 / HOME

#### 오늘의 목적을 고르고, 나와 맞는 후보부터.

방문 목적을 먼저 선택하고 취향에 맞는 카페를 살펴보도록 구성했습니다.

CAPTION: HOME · 실제 프로토타입

목적 선택

공부·작업, 데이트처럼 오늘 필요한 경험을 선택합니다.

추천의 맥락

일치율은 데모 기준이며 검증된 추천 성능 수치가 아닙니다.

03 / EXPLORE

#### 이름으로 찾고, 조건으로 좁히기.

검색과 필터를 통해 원하는 조건의 카페를 탐색하고 목록과 지도로 비교합니다.

CAPTION: EXPLORE · 실제 프로토타입

검색의 시작점

이 캡처는 “소일”을 검색한 실제 데모 상태입니다.

다른 역할의 조건

취향은 추천 순서에, 가격과 이동 반경은 검색 조건에 반영합니다.

04 / SAVED

#### 지금의 관심을, 다음 방문으로.

카페를 저장하고 다시 확인하는 흐름을 연결했습니다.

CAPTION: SAVED · 실제 프로토타입

CAPTION: SAVED-EMPTY · 실제 프로토타입

저장한 후보

실제로 데모에서 저장한 카페가 표시된 상태입니다.

아직 저장이 없다면

빈 화면에서도 탐색으로 이어지는 다음 행동을 제공합니다.

05 / MY TASTE

#### 내 취향을 한눈에, 변경은 언제든.

설정한 선호 조건을 모아 보여주고 수정하거나 추천으로 돌아갈 수 있게 구성했습니다.

CAPTION: PROFILE · 실제 프로토타입

선호 조건 요약

기억해야 할 조건을 화면이 대신 정리합니다.

재설정 동선

선택한 취향을 고정된 정답처럼 다루지 않습니다.

07 / REFLECTION

### 선택을 돕는 구조, 더 검증할 경험.

가장 고민했던 부분

개인의 취향과 방문 목적을 하나의 추천 경험으로 연결하는 과정이었습니다. 사용자가 복잡한 조건을 직접 조합하지 않아도 후보를 발견할 수 있도록 정보 구조와 탐색 흐름을 고민했습니다.

중요하게 생각한 점

카페의 분위기를 전달하면서도 필요한 정보를 빠르게 파악할 수 있는 구성이었습니다. 사진을 중심으로 시각적 매력을 살리고, 추천 정보와 필터의 위계를 정리했습니다.

배운 점과 다음 검증

좋은 UI는 사용자의 선택 과정을 자연스럽게 돕는 구조에서 시작한다고 생각합니다. 취향 설정의 부담과 추천 이유의 이해도는 앞으로 사용자 테스트를 통해 검증할 계획입니다.
