# 프로젝트 설명력을 높이는 콘텐츠 구조

이 문서는 외부 연구 수치나 인터뷰를 생성하지 않는다. 모든 근거는 실제 프로젝트 자료에서 채운다.

## 첫 화면: 빠르게 파악할 요약
프로젝트명 / 한 문장 문제 / 대상 사용자 / 담당 범위 / 기간 / 팀 구성 / 대표 결과.
팀 성과와 개인 기여를 구분하고 미측정 성과는 '검증 예정'으로 표시한다.
대표 결과가 없으면 숫자를 만들지 말고 어떤 설계 결정을 도출했는지 요약한다.

## 각 핵심 판단: 다섯 칸
1. 관찰: 어떤 사용 상황에서 무엇이 어려웠는가.
2. 근거: 인터뷰/관찰/테스트/데이터 중 어떤 자료가 이를 보여주는가.
3. 대안: 고려한 선택지와 제외한 이유는 무엇인가.
4. 결정: 화면의 어느 부분을 어떻게 바꿨는가.
5. 검증: 무엇을 측정했고 결과와 한계가 무엇인가.

실제 UI와 설명을 가까이 배치한다. 한 화면에 모든 리서치 결과를 나열하기보다 핵심 주장마다 읽을 수 있는 증거를 둔다.

## IVI에 적용할 질문
- 15개 인터페이스에서 4가지 유형을 분류한 기준은 무엇인가.
- 같은 과제를 비교할 때 통제한 조건과 바뀐 조건은 무엇인가.
- 레이아웃마다 어떤 과제에서 차이가 있었고, 어느 정도의 관찰 범위까지 설명 가능한가.
- 수행시간·클릭 수·클릭 오류율·부담·만족도는 각각 무엇을 측정하는가.
- 참여자 15명과 실험 장비/주행 상황이 결과의 일반화에 어떤 한계를 주는가.
- 측면 메뉴와 하단 공조를 결합한 하이브리드 제안은 어떤 연구 결과에서 나왔는가.
- 원래 실험한 4개 화면과 후속 설계 제안의 검증 상태를 구분했는가.
- 이번 지도 스타일 갱신이 시각 개선이라면, 과거 실험 당시 캡처와 현재 업데이트된 캡처를 구분했는가. 지도 갱신 이후에도 과거 실험 결과가 그대로 재검증된 것처럼 보이지 않도록 촬영/버전 정보를 붙인다.

## 프로젝트별 강조점 제안
- LG: 사용 맥락 → 핵심 작업 흐름 → UI 결정 → 실제 프로토타입 동작. 개인 기여를 화면과 연결.
- IVI: 실험 설계 → 비교 지표 → 해석 → 후속 설계 제안. 관찰한 결과와 추정한 효과 구분.
- CAFEKOK: 취향·목적에 따른 탐색 문제 → 추천/필터 구조 → 실제 흐름. 아직 수행하지 않은 사용자 테스트는 계획으로 표시.
- OFFER: 콘텐츠 구조 → 탐색·저장·재방문 흐름 → 기기별 설계 판단. 반응형을 세 화면 나열에서 끝내지 않고 우선순위가 어떻게 달라지는지 설명.

## 필요한 증거 자산
- 실제 변경 전후 캡처 및 버전/날짜
- 읽을 수 있는 확대용 원본 UI
- 핵심 흐름 1개의 짧은 실제 시연
- 지표 표의 원본과 계산 기준
- 대안 비교 또는 설계 판단 기록
- 자신의 역할과 산출물 목록

## 콘텐츠 검토 기준
핵심 주장마다 근거가 존재한다. 캡션에 화면의 역할·상태가 명확하다. 수치를 클릭하거나 선택해도 문맥을 잃지 않는다. 실패와 제약도 후속 판단으로 연결된다. 모션을 보지 않아도 프로젝트가 이해된다.
