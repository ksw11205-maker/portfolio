# 쉘과 상세페이지 수정 명세
작성일: 2026-11-15. 최신 사용자 요청을 반영한 준비 문서다. 사이트 구현·실행·배포는 수행하지 않았다.

## 확정한 흐름
인트로 → 오브젝트 중심 히어로 → 이름·프로필·이력 → HOW I WORK → 프로젝트 → Q&A → 파도 전환 → Contact → 작은 쉘 푸터.
프로젝트 순서는 현재의 LG → IVI → CAFÉKOK → OFFER를 유지한다. 이전 제안의 프로젝트 재정렬과 Q&A 통합은 적용하지 않는다.
인트로/히어로는 새로 설계하고, 프로젝트의 표지 확대 진입과 Q&A·Contact의 장점은 보존한다.

## 인트로와 히어로
개인 심볼의 서로 맞물리는 두 형상을 실버와 코발트 소재의 입체 오브젝트로 확장한다. 기존 symbol.svg의 고유 실루엣을 유지하며 임의의 구·토러스·AI 문자로 대체하지 않는다.
제안 장면: 재질이 보이는 근접 장면 → 두 조각의 정렬·맞물림 → 카메라가 빠지며 전체 심볼과 타이포 등장 → 첫 스크롤에서 오브젝트가 물러나며 프로필로 연결.
인트로와 히어로에 서로 다른 장식물을 반복하지 않고 하나의 오브젝트로 연결한다. 정지 포스터도 독립적으로 완성되어야 한다.
초기 연출 후보는 약 1.2–1.6초이며, 강제 로더나 스크롤 잠금으로 사용자를 기다리게 하지 않는다. 반복 진입은 짧게 처리하고 동작 축소에서는 정적 심볼·이름을 즉시 노출한다.
쉘의 시작과 Q&A는 딥 차콜을 중심으로 잡는다. 밝은 전환의 주인공은 Contact로 남기고 파란색은 심볼·선택 상태에 제한한다.

## 이름과 이력
정확한 사실은 docs/projects/profile.md와 profile-content-20261115.json을 따른다.
이름, 정체성 한 문장, 짧은 소개 다음에 EXPERIENCE / EDUCATION / CERTIFICATIONS / AWARDS를 구분한다.
SBS 수강 과정과 미토 과정은 교육 경험으로 EXPERIENCE에 배치한다. 교육을 근무 경력으로 보이게 쓰지 않는다.
UXU LAB은 연도 수준의 이력과 실제 참여 과제를 연결하고, 개인 기여가 확인된 범위만 표시한다.
도구 숙련도를 임의의 퍼센트 막대로 표현하지 않는다.

## HOW I WORK와 Q&A의 역할
HOW I WORK는 작업 과정과 도구의 용도를 보여준다. Q&A는 선택 기준·완성도·AI·협업에 대한 짧은 답을 보여준다.
HOW I WORK의 제안 축:
- 맥락을 먼저 파악한다: 사용자·과제·제약을 정리하고 연구·관찰을 판단 근거로 연결.
- 구조를 화면으로 만든다: 정보 우선순위·흐름·컴포넌트를 Figma와 프로토타입으로 구체화.
- 구현하며 점검한다: 웹 구현과 피드백으로 실제 동작·반응형·표현을 다듬음.
GPT/Codex는 탐색과 구현 지원, Photoshop/Illustrator는 이미지·그래픽, After Effects는 모션, HTML/CSS/JS는 동작 구현에 연결한다.
'AI로 빠르게 검증'은 실제 사용자 검증과 혼동될 수 있어 '아이디어를 빠르게 구체화'로 수정한다. 측정·평가를 수행한 경우에만 검증으로 기술한다.

## 프로젝트 소개와 표지 진입
현재의 표지 중심 소개를 유지한다. 제목·핵심 설명·역할은 실제 텍스트로 두고, 누른 표지가 화면 전체로 확대되며 상세로 이어지게 한다.
표지의 기기·UI 구도가 확대 전후에 일치해야 한다. 상세 진입 순간 이미지가 다른 그림으로 바뀌지 않는다.
텍스트 뒤에는 프로젝트 색에서 가져온 국소 그라데이션을 깐다. 표지 전체에 진한 색을 덮어 작업물을 가리지 않는다.
데스크톱은 실제 클릭한 표지 위치에서 확대, 모바일과 동작 축소는 짧은 전환 또는 즉시 이동. 브라우저 뒤로 가기와 기본 링크는 유지한다.
표지의 텍스트를 PNG에 굽지 않는다. 초점·선택·터치에서도 같은 상세 진입 동작을 제공한다.

## 프로젝트별 표지와 스타일
LG: 노트북 전경 + TV 배경. 실제 AI 도구와 TV 화면을 사용한다. 차콜·백색·절제된 플럼으로 연구와 도구의 정밀함을 표현한다.
IVI: assets/projects/ivi-cover-clean-1920.jpg의 기존 컨셉 목업을 메인과 상세 표지에서 함께 사용한다. 4개 실험 레이아웃 캡처를 상세 표지로 바꾸지 않는다. 본문에서는 개념 목업·실험 화면·후속 제안을 구분한다.
CAFÉKOK: 현재 cafe-cover 사진을 유지한다. 따뜻한 건축적 배경에 실제 홈 화면을 넣은 한 대의 큰 휴대폰. 상세 표지에서 기기 자체가 충분히 크게 읽히게 한다. 웜 아이보리·커피 브라운·사진의 녹색이 중심이다.
OFFER: 중앙 데스크톱 + 왼쪽 태블릿 + 오른쪽 모바일. 같은 Explore 페이지의 4열/2열/1열을 실제 캡처로 보여준다. 기기는 조금 겹치되 화면의 핵심 내용은 가리지 않는다. 백색·블랙·제한된 오렌지와 높은 정보 밀도로 구분한다.
본문은 각 프로젝트의 리듬·이미지 배열·밀도·배경을 다르게 설계하고, 포인트 컬러는 선택 상태와 핵심 판단에만 사용한다.

## 이미지 제작과 품질
새 표지 연구 이미지 3개는 조명·구도 확인용 생성 시안이다. 실제 UI의 세부 글자·날짜·수치가 원본과 픽셀 단위로 동일한 최종 증거가 아니다.
최종 표지는 생성된 배경/디바이스와 실제 원본 UI를 분리해 합성한다. 목업의 광원·반사 때문에 화면 대비가 무너지지 않도록 한다.
원본 자산 해상도를 확인하고, 가능한 경우 Figma 원본 내보내기 또는 승인된 실제 캡처로 보강한다. 낮은 해상도를 단순 확대하거나 생성 모델로 글자를 다시 만들어 증거처럼 사용하지 않는다.
모바일 상세에서는 기기를 충분히 크게 보여주며, 본문 캡처는 가능한 한 원본 픽셀을 유지한다.
내용에 맞는 실제 보유 이미지·아이콘·설명용 시각화를 우선 사용한다. 실제 실험 사진과 생성 컨셉 이미지는 구분한다.

## 프로토타입과 사이트 진입 버튼
허용 위치는 상세 표지의 CTA와 오른쪽 하단의 플로팅 CTA 두 곳이다. 사용자 요청의 '표지에도 버튼'을 표지 예외로 해석한다.
표지 CTA가 보이는 동안 플로팅 CTA는 숨기고, 표지를 지나면 플로팅 CTA를 표시한다. 두 CTA의 목적지는 같아야 한다.
본문의 '크게 보기', '직접 보기', '원본 확대' 같은 중복 버튼과 이미지별 확대 버튼은 제거 대상이다.
읽기용 표·아카이브 펼치기·목차 등 내용 접근 기능을 프로토타입 버튼과 혼동해 삭제하지 않는다.
종료 내비게이션·모바일 안전 영역과 플로팅 버튼이 겹치지 않게 배치한다. 터치와 키보드에도 명확한 이름과 초점을 제공한다.

## 상세 푸터
큰 쉘 Contact를 모든 상세에 반복하는 대신 이전·다음 프로젝트의 표지 내비게이션을 우선한다.
첫 프로젝트는 다음, 마지막은 이전, 중간은 이전·다음 표지를 제공하고, 전체 작업 링크는 항상 둔다.
그 아래에는 이름·메일·저작권으로 구성한 작은 공통 푸터를 사용한다. 내비게이션의 모양·글자 위계는 쉘과 통일한다.

## Q&A와 Contact
Q&A는 기존 5개 오브젝트를 우선 유지한다. 문구 제안은 qa-content-20261115.json을 따른다. 자료 기반 검토이며 실시간 화면 동작 감사가 아니다.
파도 전환은 어두운 Q&A에서 밝은 Contact로 크게 밝아지는 현재의 경험을 유지한다. 번쩍임보다 곡면·레이어가 올라오며 밝아지는 전환을 정교하게 다듬는다.
Contact는 기존 밝은 마무리와 메탈 명함·메일 동선을 보존한다. 문구 1순위는 “Let’s Shape What’s Next.”, 대안은 “Make the Next Move.” / “From Insight to Impact.”다. 마지막 문구는 성과 주장처럼 읽히지 않는 짧은 초대 문장으로 사용한다.
추천 보조 문장: “다음 경험의 시작, 함께 만들고 싶습니다.”
쉘 푸터는 Contact 아래 얇은 구분·이름·메일·저작권·맨 위로 이동 정도로 마감한다. 중복 연락 버튼·추가 장식·SNS 자리표시자를 만들지 않는다.

## 확인 상태
기존 자산과 소스·이력서 텍스트는 검토했다. 웹사이트를 새로 실행하지 않았으므로 화면 확대 전환, 그라데이션 대비, 실제 스크롤, 파도·키보드·터치 동작의 시각 QA는 후속 구현 검수 대상이다.
