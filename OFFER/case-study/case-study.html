04 / SCREEN BY SCREEN

여섯 화면, 여섯 가지 목적.
기능과 배치에 이유를 담았습니다.

완성된 화면에서 사용자가 무엇을 하려는지 짚고, 어떤 정보와 행동이 그 목적을 돕는지 설명합니다. 아래 설계 의도는 구현 기준이며, 사용자 테스트로 검증된 성과를 뜻하지 않습니다.

01 / HOME

관심이 정해지지 않은 순간에도,
발견을 시작할 수 있게.

사용자의 목적 · 어떤 브랜드에 어떤 혜택이 있는지 가볍게 둘러보기.

화면 직접 보기 ↗ (새 탭)
OFFER / HOME 실제 구현 화면
  1. 01

    검색과 둘러보기, 두 입구

    브랜드나 행사명을 아는 사용자는 첫 화면의 검색으로 바로 진입합니다. 아직 목적이 없는 사용자는 브랜드 모음과 대표 프로모션에서 탐색을 시작합니다.

  2. 02

    강약이 있는 프로모션 배치

    대표 카드 하나와 보조 카드 두 개로 우선순위를 만듭니다. 카드마다 브랜드 → 제목 → 최대 할인 → 기간·상태 순서를 맞춰 다른 혜택도 같은 기준으로 읽게 했습니다.

  3. 03

    다음 방문까지 이어지는 홈

    마감 임박은 진행 중인 혜택을 종료일순으로 보여줍니다. 팔로우한 브랜드의 진행 중 혜택은 홈 하단에 모으며, 팔로우가 없으면 브랜드 선택으로 안내합니다.

모바일에서는 마감 임박과 카테고리를 신규 혜택보다 먼저 배치합니다. 보조 카드는 이미지와 정보를 나란히 두어 스크롤 길이를 줄였습니다.

02 / EXPLORE

막연한 관심을,
비교할 수 있는 조건으로.

사용자의 목적 · 원하는 브랜드와 이용 가능한 시점에 맞는 혜택 찾기.

화면 직접 보기 ↗ (새 탭)
OFFER / EXPLORE 실제 구현 화면
  1. 01

    범주에서 세부 조건으로

    검색과 카테고리 아래에 브랜드·진행 상태를 배치했습니다. 검색어, 카테고리, 브랜드, 상태가 함께 적용되므로 “패션 / Nike / 진행 중”처럼 범위를 단계적으로 줄일 수 있습니다.

  2. 02

    찾는 기준과 보는 순서 분리

    필터는 목록에 포함될 혜택을 정하고, 정렬은 그 목록을 읽는 순서만 바꿉니다. 추천·최신 등록·마감 임박·최대 할인율을 비교 목적에 맞게 선택합니다.

  3. 03

    결과가 없어도 길을 잃지 않게

    결과 수와 선택한 조건을 유지하고, 0건일 때 조건 초기화를 제공합니다. 조건은 주소에도 반영되어 상세 확인 후 돌아오거나 새로고침해도 이어서 탐색합니다.

데스크톱 4열, 태블릿 2열, 390px 모바일 1열. 모바일에서는 브랜드·상태를 나란히 두고 정렬을 다음 줄로 내려 각 조작 영역을 확보했습니다.

03 / OFFER DETAIL

할인율을 보는 순간에서,
이용 여부를 판단하는 순간으로.

사용자의 목적 · 실제로 나에게 적용되는 혜택인지 조건까지 확인하기.

화면 직접 보기 ↗ (새 탭)
OFFER / OFFER DETAIL 실제 구현 화면
  1. 01

    핵심 판단 정보를 첫 화면에

    브랜드, 행사명, 최대 할인율, 기간·상태를 상단에 모았습니다. 할인율 바로 아래에 대상 상품별 차이를 알리고 “이용 조건 먼저 확인하기”를 두어 숫자만 보고 오해하지 않도록 했습니다.

  2. 02

    혜택에서 예외 조건까지 순서대로

    주요 혜택 → 참여 브랜드 → 일정 → 제외 상품·쿠폰 조건 순으로 상세 내용을 읽습니다. 저장은 조건 확인을 마치지 않아도 잠시 관심을 보관할 수 있는 보조 행동입니다.

  3. 03

    연결 목적지를 정확하게

    하단 버튼은 “공식 홈페이지”라고 명시하며 새 탭 이동을 안내합니다. 가상 프로모션이 실제 이벤트와 연결된 것처럼 보이지 않도록 데모 범위도 함께 표시합니다.

데스크톱에서는 브랜드 비주얼과 요약 정보를 병렬로 비교합니다. 태블릿·모바일은 비주얼 → 요약 → 상세 조건으로 한 열에 쌓아 읽기 순서를 유지합니다.

04 / SAVED

마음에 든 혜택을,
필요한 시점에 다시 찾도록.

사용자의 목적 · 당장 결정하지 않은 개별 프로모션을 모아 재확인하기.

화면 직접 보기 ↗ (새 탭)
OFFER / SAVED 실제 구현 화면
  1. 01

    새로 저장한 혜택부터

    모든 카드와 상세에서 같은 하트 액션을 제공합니다. 저장 화면은 최근 저장한 순서로 보여주므로 방금 보관한 혜택을 다시 찾기 쉽습니다.

  2. 02

    상태별로 다시 읽는 목록

    전체·진행 중·예정·종료와 각 개수를 보여줍니다. 종료된 혜택을 자동 삭제하지 않아 사용자가 저장한 항목이 사라진 이유를 추측하지 않아도 됩니다.

  3. 03

    빈 상태와 해제 이후까지

    첫 저장 전에는 Explore로, 선택한 상태에 결과가 없을 때는 전체 저장으로 안내합니다. 해제 후에는 인접한 저장 버튼으로 키보드 초점을 옮겨 작업을 이어갈 수 있게 했습니다.

저장은 이 브라우저의 저장 공간을 사용합니다. 계정 동기화나 만료 알림 기능을 구현한 것으로 표현하지 않습니다.

05 / FAVORITES

행사 하나를 넘어,
브랜드에 대한 관심을 모으기.

사용자의 목적 · 계속 살펴볼 브랜드를 정하고 다음 탐색의 기준 만들기.

화면 직접 보기 ↗ (새 탭)
OFFER / FAVORITES 실제 구현 화면
  1. 01

    Saved와 다른 저장 단위

    Saved는 개별 행사, Favorites는 브랜드를 보관합니다. 화면 상단에서 서로의 역할을 설명하고 연결하여 “무엇을 저장했는지”를 구분하게 했습니다.

  2. 02

    내 브랜드와 전체 브랜드 분리

    팔로우한 브랜드를 먼저 보여주고 진행 중 혜택 수와 상세 진입을 제공합니다. 아래 전체 브랜드 목록에서는 새로운 브랜드를 발견하고 같은 버튼으로 팔로우를 관리합니다.

  3. 03

    선택이 홈으로 이어지게

    팔로우 상태는 브랜드 목록·상세·홈에서 함께 반영됩니다. 관심 브랜드가 없을 때는 같은 화면의 브랜드 선택 영역으로 바로 이동합니다.

팔로우는 현재 샘플 컬렉션 안에서 개인화된 탐색을 제공합니다. 실시간 새 행사 수신이나 푸시 알림을 의미하지 않습니다.

06 / BRAND DETAIL

관심 있는 브랜드의 혜택을,
한곳에서 이어서 살펴보기.

사용자의 목적 · 특정 브랜드가 제공하는 혜택과 공식 접점 확인하기.

화면 직접 보기 ↗ (새 탭)
OFFER / BRAND DETAIL 실제 구현 화면
  1. 01

    브랜드 맥락을 먼저

    로고·분류·설명을 상단에 모아 탐색 중 이동한 브랜드를 확인합니다. 팔로우와 공식 홈페이지 링크를 인접하게 두어 내부에서 모아보기와 외부 방문을 선택합니다.

  2. 02

    진행 중과 지난 혜택 모두

    이 브랜드에 속한 프로모션만 모으고 전체·진행 중·예정·종료로 나눕니다. 진행 중인 행사가 없어도 지난 기록과 다음 예정 항목을 확인할 수 있습니다.

  3. 03

    행사 확인으로 연결되는 카드

    홈·탐색과 동일한 카드 형식을 사용해 새 규칙을 배우지 않고 상세로 이동합니다. 결과가 없는 상태에서는 이 브랜드의 전체 혜택으로 복귀합니다.

현재는 12개 브랜드의 공식 홈페이지로 연결합니다. 브랜드 제휴, 자동 행사 수집, 실제 이벤트 상세 URL 연동은 후속 검증 과제입니다.

05 / RESPONSIVE DESIGN

화면이 작아져도,
탐색의 흐름은 선명하게.

단순히 크기를 줄이지 않고, 카드의 열 수와 콘텐츠 순서를 조정합니다. 모바일에서는 마감 임박과 카테고리를 더 앞에서 만납니다.

정보의 순서는 유지하고브랜드 → 행사 → 혜택 → 기간이라는 카드의 읽기 순서는 세 화면에서 같습니다.

행 수와 조작 위치를 바꾸고가로 공간이 줄면 카드 열 수를 줄이고 필터가 다음 줄로 흐르도록 조정했습니다. 391–767px에서는 2열을 사용합니다.

행동은 모든 기기에서 동일하게검색·필터·저장·팔로우를 모두 제공합니다. 작은 화면에서 핵심 행동을 생략하지 않았습니다.
